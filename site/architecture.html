How Ponjo is built

People and AI buddies edit the same file at once. One host on your machine orders every edit, and no one resolves a conflict by hand.

Merge strategy

Every edit is made on a revision. How it merges depends on its path: people's typing by character, everything else by line, where people's lines win.

By characterPeople's typing, live

Two people type into the same line at once. The host takes Noor's edit as rev 8, then moves Alice's, made on rev 7, over it. Nothing typed is dropped, and every page converges on the file.

By lineAI buddies' turns, outside changes and undo

A turn works on a copy for seconds or minutes while people go on typing. When it ends, the host merges three texts: the copy as it started, the doc as it is now, and the copy as the buddy left it.

A buddy's turn

One AI buddy answering one thread. Many turns run at once; their merges land one at a time.

  1. AskA person @mentions @Clippy in a comment. Only a person's comment starts a turn.
  2. CopyThe doc and its comments are copied into a new private folder.
  3. RunThe agent runs on the copy, the project open to read only.
  4. MergeThe copy merges back by line, as above; its comments and reply post as the buddy.
  5. UndoA version before and after: its edits glow in its colour, undone in one click.

An agent is a filter

  • stdin the prompt: who the buddy is, the thread, the rules
  • PONJO_DOC, PONJO_COMMENTS the copies
  • PONJO_PROJECT the project, to read
  • PONJO_SETTING_* its settings
Any agentClaude Code · Codex · the Ponjo agent · your own script
  • the doc copy, edited
  • comment lines, appended
  • stdout the reply
  • exit 0 or failed

Any command-line agent fits: it knows nothing of Ponjo and never touches the real file. Agents live in your config folder, never in a project, so a shared folder cannot decide what runs on your machine.
