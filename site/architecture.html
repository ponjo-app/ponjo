How Ponjo is built

One host on your machine orders every edit. You, teammates in a browser, AI buddies and other programs are all writers through the same door, and the files stay plain text.

What is new

One team, not turnsPeople and AI buddies write the same file at once. An @mention starts a buddy; no one waits for the doc to be handed back.
No one resolves a conflictTwo merges, by the path an edit takes: people's typing by character, everything else by line, where people's lines win.
An agent is a filterAny command-line agent: a prompt in, a copy to edit, a reply out. It knows nothing of Ponjo and never touches the real file.
Every AI edit can be undoneUndo is one more merge: a turn's change taken back, while everything written since stays.
Files are the truthA doc and its comments sidecar, on your disk. Teammates join from a link; the relay between you stores nothing.

Writing together: two merges

Every edit is operations on the revision it started from. How it merges depends on its path, never on who wrote it.

By characterPeople's typing, live

Two people type into the same line at once. The host takes Noor's edit as rev 8, then moves Alice's, made on rev 7, over it. Nothing typed is dropped, and every page converges on the file.

By lineAI buddies' turns, outside changes and undo

A turn works on a copy for seconds or minutes while people go on typing. When it ends, the host merges three texts: the copy as it started, the doc as it is now, and the copy as the buddy left it.

A buddy's turn: the agent runtime

A turn is one AI buddy answering one thread. The Runner keeps the running turns equal to the asks in the comments: many run at once, their merges land one at a time.

  1. AskA person's comment @mentions @Clippy. Only a person's comment starts a turn, never a buddy's or a file's.
  2. CopyThe doc and its comments are copied into a new private folder.
  3. RunThe agent program starts there, the project open to read only.
  4. MergeOn exit 0 the copy merges back by line; its comments and reply post as the buddy, with the asker's level.
  5. ShowIts edits glow in its colour; under its reply, how many places it changed, and Undo.

The contract: an agent is a filter

  • stdin the prompt: who the buddy is, the thread, the rules
  • PONJO_DOC, PONJO_COMMENTS the copies
  • PONJO_PROJECT the project, to read
  • PONJO_SETTING_* its settings
Any agentClaude Code · Codex · the Ponjo agent · your own script
  • the doc copy, edited
  • comment lines, appended
  • stdout the reply
  • exit 0 or failed

Agents live in your config folder, never in a project: a shared folder cannot decide what runs on your machine.

The Ponjo agent: the model proposes, the program applies

Our own agent for only what co-writing needs. Its tools are its permissions: no shell, and no network but the model's API.

Promptthe doc with line numbers, the project's file names
inferAnthropic · OpenAI-compatible · Nebius
readfindgrepweb fetch commentresolvepropose results go back to infer, up to 20 steps
  • Read by line number, write by quote. propose edits as { old, new }; each old must be found once, or the whole proposal is sent back to fix.
  • Stateless. A turn remembers nothing after it; its messages are its state, and its trace replays it.
  • Runs anywhere. The turn imports nothing, so the online preview runs the same one in the browser.
